## 2. 核心口径（必须先统一，否则后面全错）

### 2.1 分数层级

| 层级 | 口径 |
|---|---|
| 题目分（已有） | 每道题 0–100，Agent 按题目的评分标准打分，落 `assessment_answers` |
| 考察点分（新增） | 该考察点下所有已评分题目的算术平均 |
| 维度分（新增） | 该维度下所有已考察点的算术平均 |
| 综合分（新增） | 六个维度分的算术平均（本次没考到的维度不参与） |
| 能力等级（新增） | 由综合分划档得到 L0–L5 |

三条规则：

1. **只统计本次测评实际出过、且评分成功的题目**，不把没考的维度按 0 分计入。
2. **评分失败的题目不参与聚合**，不伪造 0 分（沿用现有规则）。
3. **考察点是技能树的节点单位，维度是雷达图的单位。**

### 2.2 班级隔离

所有查询都必须带 `class_id`：

| 数据 | 隔离口径 |
|---|---|
| 班级分数 | 该学生在该班级下**最新一次**测评的综合分 |
| 能力等级 | 由上面那个分数划档，只代表该班级 |
| 雷达图 / 技能树 | 该班级下最新一次测评的维度分 / 考察点分 |
| 成长趋势 | 该班级下的历史测评，按时间排序 |
| 上一次对比 | 该班级下的最近两次测评 |

同一个学生在 A 班是 L4、在 B 班是 L2，是正常且必须支持的。

### 2.3 等级划档（建议值，可配置）

| 综合分 | 等级 | 名称 |
|---|---|---|
| 无测评记录 | L0 | 等待启程 |
| 0–59 | L1 | 基础认知者 |
| 60–69 | L2 | 工具使用者 |
| 70–79 | L3 | 应用进阶者 |
| 80–89 | L4 | 人机协同专家 |
| 90–100 | L5 | 创新应用者 |

划档逻辑放在**后端**（班级看板、教师端也要用同一套口径），前端只做展示。阈值写成配置项，方便以后调。

## 3. F2 + F3：评分系统

### 3.1 现状盘点（已经有了什么）

| 能力 | 位置 | 现状 |
|---|---|---|
| 单题评分 | `app/agent/scoring_tool.py` 的 `score_topic` | 调一次模型，返回 score / reason / evidence / confidence |
| 评分触发 | `app/assessment/flow.py` 的 `_close_question()` | 一道题问完时触发，成功写 `scored`，失败写 `scoring_failed` |
| 落库 | `assessment_answers` 表 | 每题一条：score、scoring_reason、scoring_evidence、confidence、result_status、scored_at |
| 总分 | `flow.py` 的 `_finish()` | 已评分题目的算术平均，写 `assessments.total_score` |
| 对外接口 | `POST /internal/v1/agent/score` | 可单独调用 |

**结论：单题评分链路是完整的，不用重做，只需要两件事——把评分封装成可替换的工具，再补上维度/考察点的聚合与落库。**

### 3.2 F2：把评分做成「工具」

目标：你朋友后续要改评分算法，只改一个文件，不碰流程代码。

设计（与现有 `QuestionEngine` 的策略注入方式保持一致）：

| 组件 | 职责 |
|---|---|
| `ScoringTool`（协议） | 评分能力的统一入口，换算法 = 换这个实现 |
| `LlmScoringTool` | 默认实现，包住 `score_topic` 与提示词，行为与现在完全一致 |
| `Aggregator` | 确定性聚合，不调模型：题目分 → 考察点分 → 维度分 → 综合分 → 等级 |

改造点：

1. `AssessmentFlow.__init__` 增加可选参数 `scoring_tool`，默认 `LlmScoringTool`（向后兼容，现有测试不受影响）。
2. `_close_question()` 里把 `self.agent.score(...)` 换成 `self.scoring_tool.score(...)`。
3. `_finish()` 里调用 `aggregator.aggregate(...)`，把结果落库。
4. `POST /internal/v1/agent/score` 接口保持可用，行为不变。

替换算法的示例（给你朋友看）：

```python
class MyScoringTool:
    name = "my-algorithm"

    async def score(self, request):
        ...

flow = AssessmentFlow(agent, repository, settings, scoring_tool=MyScoringTool())
```

### 3.3 F3：维度分与考察点分落库

**新增两张表**（追加到 `database.sql` 的增量迁移段）：

```sql
-- 维度分：一次测评 × 一个维度，最多 6 行
CREATE TABLE IF NOT EXISTS assessment_dimension_scores (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  assessment_id BIGINT NOT NULL,
  class_id BIGINT NOT NULL,
  student_user_id BIGINT NOT NULL,
  dimension VARCHAR(120) NOT NULL,
  score DECIMAL(6,2) NOT NULL,
  question_count INT NOT NULL DEFAULT 0,
  created_at TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_assessment_dimension(assessment_id, dimension),
  INDEX idx_class_student(class_id, student_user_id)
);

-- 考察点分：一次测评 × 一个考察点，最多 20 行（技能树数据源）
CREATE TABLE IF NOT EXISTS assessment_point_scores (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  assessment_id BIGINT NOT NULL,
  class_id BIGINT NOT NULL,
  student_user_id BIGINT NOT NULL,
  dimension VARCHAR(120) NOT NULL,
  assessment_point VARCHAR(160) NOT NULL,
  score DECIMAL(6,2) NOT NULL,
  question_count INT NOT NULL DEFAULT 0,
  created_at TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_assessment_point(assessment_id, assessment_point),
  INDEX idx_class_student(class_id, student_user_id)
);

-- assessments 补两列：综合分、等级
ALTER TABLE assessments
  ADD COLUMN average_score DECIMAL(6,2) NULL,
  ADD COLUMN ability_level VARCHAR(4) NULL;
```

写入时机：测评收尾时（Agent 的 `_finish()`）一次性写入，**幂等**（用 `ON DUPLICATE KEY UPDATE`，重复收尾不会重复计数）。

### 3.4 验收标准

1. 完成一次测评后，`assessment_dimension_scores` 里能查到本次考到的维度分，`assessment_point_scores` 里能查到考察点分。
2. 考察点分 = 该考察点下题目分的平均；维度分 = 该维度下考察点分的平均；综合分 = 维度分的平均。用一组已知数据能手工对上。
3. 评分失败的题目不计入任何聚合。
4. 把 `scoring_tool` 换成假实现，`_close_question` 与 `_finish` 正常跑通（证明可替换）。
5. 现有 68 个 Python 测试全部通过。
6. 重复调用收尾接口，分数记录不重复、不翻倍。

## 4. F4 + F5 + F11：班级分数与等级

### 4.1 后端取数逻辑

取该学生**在指定班级下**最新一次已完成的测评：

```sql
SELECT * FROM assessments
WHERE class_id = ? AND student_user_id = ?
  AND status IN ('completed','completed_with_scoring_failure')
ORDER BY completed_at DESC, id DESC LIMIT 1;
```

然后读它的 `average_score` 和 `ability_level` 直接返回；历史数据里这两个字段为空时，用总分回退计算。

### 4.2 新增接口

```
GET /api/classes/{classId}/my-ability
```

一次返回前端要的全部数据，避免前端拼多个请求：

| 字段 | 含义 |
|---|---|
| `classId` | 班级 |
| `hasAssessment` | 该班级下有没有测评记录；false 时前端显示 L0 空状态 |
| `latest` | 最新一次测评：assessmentId、averageScore、level、levelName、completedAt |
| `dimensions` | 六维分：dimension、score、questionCount |
| `points` | 考察点分：dimension、assessmentPoint、score、questionCount |
| `trend` | 该班级下最近 N 次（建议 10 次）测评的综合分与等级，按时间升序 |
| `previous` | 上上次测评的分数与六维分；只有一次测评时为 null |

### 4.3 班级隔离的落实点

这是一个容易漏的地方，逐个点名：

| 位置 | 要求 |
|---|---|
| `GET /api/assessments` | 支持 `classId` 查询参数，不传时保持现有行为（兼容） |
| `GET /api/classes/{classId}/my-ability` | 必须校验调用者是该班级 active 成员 |
| 测评记录列表（学生端） | 按当前选中班级过滤 |
| 工作台 | 展示当前选中班级的分数与等级，切班即刷新 |
| 教师查看结果 | 只查该班级/该任务下的测评（现有逻辑已满足） |

### 4.4 验收标准

1. 同一账号在 A 班完成测评后，切到 B 班看不到 A 班的分数与等级（`hasAssessment=false`）。
2. 在 B 班再做一次测评，B 班显示 B 班的分数，A 班仍显示 A 班的分数。
3. 等级与综合分的对应关系符合第 2.3 节表格。
4. 只有一次测评时，对比区域显示「完成第二次测评后生成对比」，不报错。

## 7. F1：注册填写组织码

### 7.1 交互

注册表单新增一个**可选**字段「组织码」，提示文案：「选填，填写后自动加入该班级」。

### 7.2 实现方式（后端零改动）

组织码就是现有的**班级邀请码**（6 位数字，`class_invite_codes.code`），复用现有接口：

| 步骤 | 接口 | 说明 |
|---|---|---|
| 1 | `POST /api/auth/register/student` | 注册（现有接口，不动） |
| 2 | `POST /api/classes/join { inviteCode }` | 注册成功后自动调用（现有接口，不动） |

前端注意：

- 注册成功后**先完成登录拿到令牌**，再调 join（join 需要登录态）。
- 组织码填错不阻断注册：注册成功即算成功，join 失败时提示「注册成功，组织码无效，可在我的班级重新加入」。
- 组织码留空时直接跳过 join。
- 教师注册不涉及组织码。

### 7.3 验收标准

1. 填组织码注册 → 注册成功 → 自动进入该班级 → 「我的班级」能看到。
2. 留空注册 → 注册成功 → 不加入任何班级。
3. 填错组织码 → 注册仍成功，给出明确提示，可稍后手动加入。

## 8. 具体考察点 2.0 词表（开发直接照抄）

### AI基础认知（7 个考察点）

| 考察点 | 介绍 |
|---|---|
| AI基本概念理解 | 能准确区分 AI、机器学习、深度学习、大语言模型等核心概念及其关系；能用通俗语言向非专业人士解释这些概念 |
| 数据影响AI输出的认知 | 能说明训练数据中的偏差如何导致 AI 输出偏误；能举例说明数据质量（完整性、代表性、时效性）对 AI 生成内容准确性的影响 |
| AI决策的基本逻辑 | 能理解 AI 系统基于数据和概率做出决策的基本逻辑；能区分基于规则的系统与基于学习的系统的差异 |

| 批判性看待AI | 能对 AI 输出保持审慎态度，不盲目信任；能从技术、伦理、社会等多维度批判性评估 AI 的应用 |
