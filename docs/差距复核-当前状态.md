## 一、先说结论

**你确认要做的那批功能（F1–F11）已经全部落地。** 我在代码里逐项验证过，包括数据库新表、Agent 侧聚合、Java 侧能力接口、前端四张图和能力标准页。

现在剩下的差距，集中在朋友原型里**核心闭环之外**的部分：训练场、报告中心、通知、日历、成长统计，以及教师端的分析类页面。另外还有几项属于"能力形态"差异，改动量明显更大（客观题判分、实操任务、逐题会话）。

## 四、现在项目有、朋友原型没有（别丢）

这些是原型里连页面都没有的真实能力，是当前项目的实际价值所在：

| 能力 | 说明 |
|---|---|
| 对话式测评引擎 | 先决策后发言的双模型调用、动态追问、确定性收尾规则 |
| 发题快照不可变 | 题干/选项/评分标准/考察点冻结，题库改动不影响历史测评 |
| 自动评分与失败处理 | 逐题评分、评分失败不伪造分数、失败不计入聚合 |
| SSE 流式输出 | 六个事件，Java 原样透传字节流 |
| 断点恢复 | 刷新页面拉回整场对话与当前题目 |
| 班级邀请码 | 6 位数字码、刷新失效、退出可重入 |
| 权限与越权校验 | 服务端逐接口校验归属，Agent 二次校验 |
| 教师结果查看 | 任务完成情况汇总 + 逐题对话与评分明细 |
| 数据一致性 | 唯一键、幂等开始测评、软删除优先 |
| Agent 离线测试 | 覆盖事件序列、JSON 防护、收尾规则、出题边界、评分工具 |

## 五、建议的补齐顺序

| 第三梯队 | N3 报告中心、N8 成长统计、N6 通知、N7 日历 | 把学生的成长闭环补完整，数据已经具备 |
| 第四梯队 | N11 客观题判分、N9/N10 题号进度与计时 | 需要改测评页与判分逻辑，属于形态增强 |
| 第五梯队 | N1 训练场、N12 实操任务、N13 逐题会话 | 新形态，改动大，建议确认比赛时间是否够 |

## 六、一句话总结

**你朋友想要的那个"样子"，骨架已经搭好了**：能力画像、等级、雷达图、技能树、趋势、对比、考察点介绍、班级隔离全部到位，而且分数是真的从测评里算出来的，不是写死的。

**剩下的差距分两类**：一类是"多几个页面"（训练场、报告中心、通知、日历、教师端分析），数据基础基本都有；另一类是"换一种测评形态"（客观题判分、实操任务、逐题会话），要动测评引擎本身。
