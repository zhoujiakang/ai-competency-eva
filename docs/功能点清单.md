# AI 能力测评系统 · 功能点清单（对比基线）

> 用途：本文档是**当前项目的功能点基线**，用于与后续新增项目逐项对比。
> 每条功能点带唯一编号（`A1`、`B2`…），对比时可直接按编号标注「两边都有 / 只有本项目有 / 只有对方有」。
>
> 口径：**只收录代码里真实实现的**能力。状态说明见文末图例。实现位置一律指到具体文件。

## 0. 项目概况

| 维度 | 内容 |
|---|---|
| 系统定位 | 以**多轮对话**为主要形式的 AI 使用能力测评系统（非传统试卷） |
| 角色 | 学生、教师两个端（无管理员端、无企业端） |
| 工程规模 | 前端 React、后端 Spring Boot、Agent FastAPI 三进程 |
| 核心命题 | AI 测评官自动出题、动态追问、逐题评分、自动收尾并给出总分 |

### 0.1 技术架构

| 层 | 工程 | 技术栈 | 端口 |
|---|---|---|---|
| 前端 | `frontend-ai-assessment/` | React 19 + Vite 8 + lucide-react（无路由库） | 4174 |
| 业务后端 | `backend-java/` | Spring Boot 3.4.5 / Java 21 / MyBatis-Plus 3.5.12 / Sa-Token 1.39 / Redis / BCrypt | 8080 |
| 测评 Agent | `agent-python/` | FastAPI + LangGraph + openai SDK + aiomysql（Python 3.12） | 8090 |
| 存储 | MySQL 8（事实源）、Redis 7（登录态）、DeepSeek API（模型） | — | — |

分工主线：**Java 管业务事实，Agent 管测评过程，Java 原样透传 SSE 字节流。**

### 0.2 代码规模速览

| 项 | 数量 |
|---|---|
| Java Controller / Service / Mapper / Entity | 8 / 6 / 13（+1 基类）/ 13 |
| Java 对外接口 | 45 个（前缀 `/api`，按 `@*Mapping` 实测） |

## E. 测评过程（核心，Python Agent 主导）

| 编号 | 功能点 | 角色 | 状态 | 实现位置 / 要点 |
|---|---|---|---|---|
| E1 | 自主练习测评 | 学生（班级有效成员） | ✅ | 每次全新测评，可重复发起；考察范围由学生自选，不选 = 不限 |
| E2 | 出题引擎（可整体替换策略） | 系统 | ✅ | `tools/question_selection.py`，默认 `RandomEngine`：范围筛选 + 排除已用 + 随机抽题 |
| E3 | 考察范围筛空时回退全量题库 | 系统 | ✅ | `eligible_candidates`，避免过窄范围把测评卡死 |
| E4 | 同一题在同一测评中只出现一次 | 系统 | ✅ | 引擎排除已用题 + 唯一键 `(assessment_id, question_id)` 双保险 |
| E5 | 发题冻结不可变快照 | 系统 | ✅ | 题干/选项/答案/评分标准/难度/标签/考察点全部冻结进 `assessment_questions`，题库后续修改不影响历史测评 |
| E6 | **两次模型调用结构**：先决策、再发言 | 系统 | ✅ | 决策轮静默且必须调用 `ask_followup` 或 `next_question`；发言轮再按动作选提示词并流式输出 |
| E7 | 多轮追问 | 系统 | ✅ | `DIALOGUE_SYSTEM`，一个主题可持续追问，整场是一条连续对话 |
| E8 | 模型自主判断换题 | 系统 | ✅ | 决策轮返回 `next_question` → 收尾语 + 关题 + 换题 |
| E9 | **确定性收尾规则**（不给模型追问机会） | 系统 | ✅ | `completion.py`：① 学生明确要求跳过（≤40 字且命中 `SKIP_PHRASES`）② 本题轮次达上限（默认 6 轮） |
| E10 | 逐题评分（0–100，按快照标准） | 系统 | ✅ | `agent/scoring_tool.py` 的 `score_topic()`，输出 score / reason / evidence / confidence |
| E11 | 未作答判 0 分 | 系统 | ✅ | 由**模型按提示词**判定（非代码伪造） |
| E12 | 评分失败不伪造分数 | 系统 | ✅ | 记 `scoring_failed`、分数留空、保留原始回答；整场标记含评分失败 |
| E13 | 自动换题 / 自动收尾 | 系统 | ✅ | 题目用光或达到任务题数上限 → 算总分、置状态、发 `finished` |
| E14 | 学生主动结束测评 | 学生 | ✅ | 先给「有消息的当前题」补评分，再收尾算分 |
| E15 | 断点恢复 | 学生 | ✅ | `GET /assessments/{id}/conversation` 拉回整场消息 + 当前题目 |
| E16 | SSE 六种事件 | 系统 | ✅ | `question` / `delta` / `answered` / `finished` / `done` / `error` |
| E17 | 流式 JSON 包裹防护 | 系统 | ✅ | 先攒 12 字检查开头 40 字有无 `{` / 代码块 / `"reply"`，命中则整段丢弃重试 |
| E18 | 发言轮失败兜底 | 系统 | ✅ | `ask_followup` 失败抛 502（不发空话术）；`next_question` 失败用固定收尾语，绝不卡住学生 |
| E19 | 决策轮失败降级 | 系统 | ✅ | 按「继续追问」处理，宁多问一句不草率收尾 |
| E20 | 一回合内完成「收尾 + 换题」 | 系统 | ✅ | 学生无需点「下一题」，前端不推断题序 |
| E21 | 参考选项可作为输入 | 前端 | ✅ | 有选项的题在输入框上方展示可点选按钮，也允许自由作答 |
| E22 | 中文输入法回车保护 | 前端 | ✅ | `app/ime.js` 判定组字状态，避免中文回车误提交 |
| E23 | 总分计算 | 系统 | ✅ | 已评出分数题目的算术平均，保留 2 位小数；一题未评出则留空 |

## K. 关键业务规则（对比时用于判断语义是否一致）

1. **维度与考察点是受控词表**：6 个维度、24 个考察点，前端只能点选。
2. **一道题只属于一个维度**，考察点必须来自该维度。
3. **考察范围为空 = 不限制**；范围筛空时自动回退全量班级题库。
4. **同一题在同一测评中只出现一次**（引擎 + 唯一键双保险）。
5. **题目快照不可变**，题库修改不影响进行中或历史测评。
6. **同一任务一个学生只有一次测评**；自主练习不限次数。
7. **评分失败不伪造分数**，总分标记为「包含评分失败题目」。
8. **总分 = 已评出分数题目的算术平均**。
9. **软删除优先**，历史测评始终可复核。
10. **Java 不解析测评过程**，AI 说什么、换不换题全部由 Agent 决定。
11. **自主练习测评没有题数上限**；只有教师任务有题数上限。
